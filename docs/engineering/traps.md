# Traps

## Package and dependency boundary

- **Root has two dependency roles.** The published root owns production `diff` plus `"*"` Pi peers and its lockfile; clean setup uses `npm ci --ignore-scripts --legacy-peer-deps`. Nested extension manifests/locks are development bootstrap only; use `npm run bootstrap` for their installs. Pi managed installs disable peer solving.
- **Bootstrap does not eliminate all network use.** Engineering-docs and personal-memory scripts invoke `npx --yes`; uncached TypeScript/tsx packages still require npm registry access during tests/typecheck.
- **Extension dependencies are split.** A test passing in one package does not prove another package is installed. After cloning or lock changes, run root `npm ci --ignore-scripts --legacy-peer-deps`, nested `npm run bootstrap`, then root gate. If nested workflow tests fail before source execution because `node_modules/.bin/tsx`, `tsc`, or `@types/node` is absent, bootstrap first; a temporary ignored `tsx` shim may unblock tests, but remove it afterward.
- **Runtime Pi API and extension dependency versions can differ.** Package-load smoke plus extension typechecks are both required; one does not replace other. Missing nested `tsc` is a dependency/bootstrap failure, not proof of source failure.
- **`npm pack` can fail on cache ownership.** A root-owned entry under `~/.npm/_cacache` causes `npm pack` to return `EPERM`; repair ownership for the current user, then rerun `npm run check:package`.

## Browser verification

- **Chromium is a separate prerequisite.** `playwright-core` does not download a browser; the first Pi browser tool call fails until `cd agent/extensions/browser && npx playwright install chromium` completes. Non-Pi harnesses also need the manually installed `@playwright/cli`; neither CLI nor browser is installed automatically, and missing prerequisites mean visual verification is unverified.
- **Playwright and Chromium versions can mismatch.** Browser launch errors name `npx playwright install chromium`; reinstall the managed Chromium binary before diagnosing extension behavior.
- **Browser lifecycle has page and context scopes.** `browser_close`/`browser_kill` close only caller's owner page; `/browser off`, `/new`, tree reconstruction to disabled, and `session_shutdown` close the shared persistent context. Verify no Chromium child remains after live tests.
- **Pages are lazy but explicitly capped.** Parent plus `DEFAULT_BROWSER_CONCURRENCY_CAP` child pages are allowed (four pages currently). An agent that never calls a browser tool creates no page; a fifth owner fails with page-cap exhaustion instead of silently sharing a page.
- **Buffers are per-page.** Console and network output belongs to its owner and is capped at 1,000 entries. Parent inspection cannot see child output; restricted explorer proxies force `clear:false` so read-only discovery does not drain buffers.
- **Timeout scope matters.** Browser operation timeout or abort reaps only caller's page, not the shared context or sibling pages. Channel requests also have bounded waits and require matching `requestId` and owner.
- **Explorer browser access follows parent mode.** Build injects all eight browser proxies; Discuss/Plan/Review inject only `browser_console`, `browser_screenshot`, and `browser_network`. Restricted explorers cannot retry mutation proxies; browser mutations are workflow-gated in the parent.
- **Persistent profiles retain site state.** Cookies and storage survive browser relaunches by default; set `PI_BROWSER_PROFILE` to a disposable temp directory when testing clean state.
- **Navigation waits only for DOM readiness.** `browser_goto` uses `waitUntil: "domcontentloaded"`; async requests may still be pending (`agent/extensions/browser/index.ts:579-585`).
- **Eval returns node placeholders.** DOM nodes serialize as exact `"ref: <Node>"`; Task 1 live output matched (`agent/extensions/browser/index.ts:474-496`).
- **Network failures expose Chromium error text.** `requestfailed` stores `request.failure()?.errorText`; Task 1 recorded exact `net::ERR_EMPTY_RESPONSE` for an unread fetch (`agent/extensions/browser/index.ts:756-763`).
- **`pi-tui` resize can trip its width guard.** Resize calls `requestRender()` without `invalidate()`, so stale wider lines can crash the process. Keep `ask-user-question` render caches keyed by width (`agent/extensions/ask-user-question/index.ts:243-249`, `:378-384`, `:565-571`).
- **Inline `tsx -e` is unreliable for ESM-only Pi peers.** Eval may compile as CJS and fail with `ERR_PACKAGE_PATH_NOT_EXPORTED` even after `NODE_PATH` changes. Use package tests for runtime behavior or esbuild bundling with Pi peers externalized for syntax-only checks; live behavior still needs a real Pi session.
- **The `tsx` CLI fails in the Claude Code sandbox.** Run scripts as `node --import tsx <script>` from the package directory so Node resolves that package's dependencies.

## ask_user_question context defer

- Pi's automatic compaction checks run after an agent loop (`@earendil-works/pi-coding-agent/dist/core/agent-session.js:779`) and before a non-streaming prompt (`@earendil-works/pi-coding-agent/dist/core/agent-session.js:864-868`), not at each tool-result boundary. An answered question can cross the threshold mid-run, so the extension reads `ctx.getContextUsage()` after each answered result.
- `prompt()` handles streaming input at `@earendil-works/pi-coding-agent/dist/core/agent-session.js:834-846` before its compaction check. Do not resume with `deliverAs: "followUp"`; the message queues while streaming and misses the pre-prompt check.
- `AgentSession.compact()` starts with `await this.abort()` (`@earendil-works/pi-coding-agent/dist/core/agent-session.js:1400-1402`). The extension aborts at `tool_execution_end`, then waits for `agent_settled` before sending the fresh user turn; it does not call `ctx.compact()` from tool execution.
- `tool_execution_end` is emitted in tool completion order. A mixed ask-user-question/tool run therefore needs the per-run abort/marker guard; Task 5 observed the other tool result persisted and no unpaired `tool_use`.

## Source isolation versus runtime sharing

- **Workspace isolates source, not Pi home.** Normal launcher reuses global auth, settings, model catalogs, sessions, context, and personal memory. `/login`, `/settings`, `/trust`, `/remember`, and bridge `save_memory` can change shared user state.
- **`--no-session` is not full isolation.** It prevents parent session persistence only. Use secure temporary `PI_CODING_AGENT_DIR` for live tests that save memory or alter settings, then remove it. Workflow plan storage and personal-memory writes honor this override.
- **Bridge plan saves depend on live host resolution.** If historical `MCP error -32000: Pi getAgentDir() unavailable` returns, `save_plan` failed before `writePlanFile`; preserve plan text in chat and retry only in a disposable `PI_CODING_AGENT_DIR` session. Do not add a bridge-side file fallback or use normal user state.
- **Provider overload is not source failure.** For live acceptance, retry a fresh disposable session or another suitable configured model before diagnosing code; keep all temporary auth and state isolated.
- **Never copy runtime state into repository.** Temporary auth/settings copies belong in mode-protected OS temp directories and must be deleted after test.
- **Only `.pi/agents` is tracked below `.pi/`.** Bridge creates ignored `.pi/memory/bridge/`; broad `rm -rf .pi` destroys project agent link.

## Duplicate loading and stale code

- **Pi loader aliases are build-time only.** Static bare imports are required for Pi APIs. `createRequire` and variable-specifier `import()` bypass the alias; broad catches in plan-file host discovery or `gcSessionPlans()` can hide the failure as unavailable host state or an empty plan store. `scripts/check-workspace.mjs` guards shipped entrypoints.
- **Extension auto-discovery ignores `settings.json` removal.** `loader.js:534-539` unconditionally discovers `cwd/.pi/extensions/` then `agentDir/extensions/` before configured paths. Removing `extensions` entries cannot disable either location. Keep retired global copies under `~/.pi/agent/extensions.disabled/`; use `./bin/pi-workspace` for source runs.
- **`pi -e .` can load duplicate extensions.** Without `--no-extensions`, any project-local or restored global copies remain discoverable beside workspace package. Duplicate commands, event listeners, watchers, widgets, and notifications can result.
- **Plain `pi` may load stale published bridge code.** On this host, plain `pi` loaded `npm:@lopezpetergabriel/pi-extensions@0.7.1` with the older single-lock bridge; repository work should use `./bin/pi-workspace` to load current source.
- **`--no-extensions` disables extensions only.** Global context/settings and other Pi-owned state remain available. Do not describe launcher as fully hermetic.
- **Captured `ExtensionAPI` contexts die after session replacement.** `/fork`, `/new`, session switch, or `/reload` can dispose old extension state: `@earendil-works/pi-coding-agent/dist/core/agent-session.js:573` calls runner `invalidate()` (`@earendil-works/pi-coding-agent/dist/core/runner.js:324,331`), then later API use throws from `assertActive()`. Never cache activation `pi` at module scope; thread current activation `pi` through functions/closures, as `agent/extensions/subagents/index.ts` does for effort and browser-proxy calls.
- **Running Pi keeps loaded source.** After edits, use `/reload` when supported or restart launcher before live acceptance. A passing test against disk does not prove old process reloaded.
- **Upstream docs links can lag package metadata.** When locating Pi host source, prefer the installed package's `repository` field; current `@earendil-works/pi-coding-agent` points to `earendil-works/pi`, package directory `packages/coding-agent`.

## Project marker precedence

- **Nearest ancestor `.pi` wins bridge/project discovery.** Starting below unintended marker can bind bridge IPC, project agents, and project settings to wrong root. `~/.pi` is Pi's global agent dir and never counts: a marker is a project only when its parent realpath differs from `realpath(os.homedir())`. Before this exclusion, any harness started under `$HOME` without a nearer marker (for example an Open Design workspace) was misdetected as a Pi project and had its writes blocked.
- **Cwd scope and edit-target scope differ.** Hooks decide mutation from the cwd project's lease, then separately resolve each dedicated edit target's nearest Pi root. A foreign target root needs its own lease, so a holder lease in project A never authorizes writes into project B. Relative targets resolve against the hook cwd, and the deepest existing ancestor is realpathed, so a symlinked directory cannot disguise a Pi target. Missing paths fail closed only where the previous behavior was an allow.
- **Path-less Bash and patch-style tools still bypass target checks.** The target check covers dedicated edit tools only: Claude `Edit`/`Write`/`MultiEdit`/`NotebookEdit`, Cursor `preToolUse` tools carrying `path`/`file_path`/`target_file`, OpenCode `edit`/`write`. Bash and patch-style tools with no path field can still write into a Pi project from a session outside it; this limit is documented as F11 and is not fixed. Pi Build is not target-checked either: its Build guard checks only its own project, so Pi Build in one Pi project can edit files inside another whose writer is held (F11, accepted).
- **This repository’s `.pi/agents` symlink is also the project marker.** Before bridge tests, verify `pwd`, repository `.pi`, Pi bridge status root, and test argument all refer same checkout. Never delete or replace it during cleanup; remove only ignored `.pi/memory/bridge/` or project agents and hook enforcement can disappear unexpectedly.
- **Bundled agents are always in scope.** Definitions load module-relatively. Default user scope is bundled+user; project is bundled+nearest project; both is bundled then user then project, with later same-name definitions winning. The source checkout `.pi/agents` link is only a dev/project mechanism, not npm registration. A selected valid unsafe explorer override is rejected by validation, not replaced silently. Use `agentScope: "project"` or `"both"` to add project definitions.

## Plan-mode verification limits

- **Plan sandbox is not a general test environment.** Repository/home writes and network are denied. `npm ci`, uncached `npx`, CCC init/index, live bridge IPC, and write-heavy tests require Build.
- **Pi IPC socket tests are Build-only in this environment.** Plan sandbox denies socket binds with `listen EPERM`; run socket coverage in `agent/extensions/subagents/test/test_ipc.ts` and `agent/extensions/subagents/test/test_launch.ts` in Build.
- **Sandbox failures can mimic code failures.** `EPERM` for temp/cache creation and `ENOTFOUND registry.npmjs.org` may indicate Plan restrictions. Rerun in Build before diagnosing source.
- **CCC search is an external prerequisite and not filesystem-read-only.** Install/configure the separate `ccc` CLI before using `ccc_search`; it may start a daemon, write user/project index state, and contact an embedding provider. Use dedicated `ccc_search`; never broaden generic Bash sandbox permissions. Inspect `git diff` afterward: indexing can add ignored-project metadata such as `.gitignore` entries.
- **CCC fallback is deliberate.** A timed-out or empty `ccc_search` result is not source evidence; retry with a narrower query, then use exact `rg`/`read` discovery when the index is unavailable.

## Pi ↔ harness bridge

- **Bridge ownership is per Pi session.** A second process reusing a Pi session ID becomes passive when that namespace has a fresh owner; distinct Pi session IDs can be active in one project. Stop the duplicate owner or start a fresh Pi session.
- **Clean-stop presence must be back-dated.** `stopActiveBridge()` keeps the owned namespace but writes heartbeat `now - LIVE_TTL_MS - 1`; a fresh final heartbeat makes a same-ID restart passive (`agent/extensions/claude-bridge/index.ts`, `presence.ts`).
- **Live pairing wins over restored pairing.** Within the 10m GC window, restart restores peers from its own validated presence but filters peers already present in another live namespace. Otherwise a Claude identity newly paired to Pi B could also reappear in Pi A (`presence.ts`, `index.ts`).
- **A peer can return stale within the GC window.** If Claude ends while Pi is down, `SessionEnd` cannot unpair it; its persisted identity may restore for up to 10m. GC after that window removes the namespace and peer.
- **RPC `--resume` is interactive.** In observed Pi CLI, `--resume <id>` opened a TUI picker in RPC mode; use `--session <id>` to resume a known session headlessly.
- **Bridge root follows nearest marker, not client config path.** MCP `cwd`, Pi cwd, and intended project marker must agree.
- **Bridge protocol tests mutate state.** Core tests save notes, plan, and personal memory. Run against disposable `PI_CODING_AGENT_DIR`, not normal user memory; workflow plans and personal-memory paths now use that injected root.
- **The watcher and the poll stop together.** Requests arrive through `fs.watch` plus a 500 ms poll backstop; `stopWatching()` closes both at every stop path (session switch, shutdown, ownership loss). Adding a stop path that only closes the watcher leaves a timer scanning a stale namespace (`agent/extensions/claude-bridge/index.ts`, `request-queue.ts`). Plan reads/ticks must remain live workflow-owner requests; never add a direct MCP plan-file fallback.
- **Overlapping scans interleave handlers.** `scheduleScan` coalesces scan starts (50 ms) but never waits for a running scan, and the poll starts one every 500 ms, so several request handlers can be in flight at once. Each scan still handles one file at a time and the rename claim keeps any request from running twice, but handler code must not assume it runs alone (`agent/extensions/claude-bridge/index.ts`, `request-queue.ts`).
- **Upgrading resets the health ring once.** The `health.jsonl` reload keeps only lines whose keys match the current health entry exactly, so adding a field (as `retry` did) drops every earlier line on the first start after the upgrade. Expected; nothing else depends on old entries (`request-queue.ts` `BridgeHealth`).
- **Replay only lasts as long as `processed/`.** Answers are pruned after 10 minutes, so a client reusing a request ID after that would run it again. Clients use a fresh UUID per call and stop waiting after ~32 s; keep it that way (`request-queue.ts` `RETENTION_MS`).
- **`not_delivered` depends on the withdraw rename.** Reporting it without first moving the request into `withdrawn/` lets Pi run a request the client called undelivered (`agent/claude-bridge-client/pi-bridge-mcp.js`). The bridge e2e pauses Pi to check this.
- **Pi in RPC mode can approve Build leases.** RPC mode binds a real extension UI, so `/build-lease approve` sent over RPC stdin opens the confirm dialog and whoever drives stdin can answer it. The bridge e2e relies on this; whether a harness agent could launch its own RPC Pi to self-approve is an open review item under `ADR-0045`/`ADR-0047`.
- **A killed Pi session cannot restart immediately under the same ID.** Its last heartbeat stays fresh for `LIVE_TTL_MS` (5 s), so a restart sooner becomes passive; the e2e waits 5.5 s.
- **Bridge plan state stays in memory until Pi's first assistant message.** Pi writes no session file until the session has an assistant message (`@earendil-works/pi-coding-agent` `dist/core/session-manager.js` `_persist`). A plan saved and ticked only through the bridge, in a Pi session that never got a model reply, is lost if Pi restarts or crashes: the restart warns "No project session found with id" and starts without the plan. Git commits stay the durable record, and re-ticking is idempotent. The bridge e2e makes no model calls, so after its crash restart it checks only that the Build lease was released, not that the plan survived; making bridge plan state durable is an open follow-up.
- **Any file named `memory.md` is gitignored.** `.gitignore` excludes `memory.md` everywhere to keep personal memory out of Git, so a test fixture with that name passes locally and is missing in CI. The recall fixture is `test/fixtures/recall-corpus/memory-index.md`; check new fixtures with `git check-ignore -v`.
- **tsx tests run as CommonJS here.** Top-level `await` fails with "not supported with the cjs output format" in `claude-bridge` tests and in `tsx -e` sources; wrap the body in an async function that sets a failing exit code.
- **Do not import live owner state.** Earlier direct workflow/discussion module imports produced false plan success and clobbered Notes UI. Use event-bus request/result handoff.
- **Idle widget redraw is load-bearing.** Capture success requires live owner update while Pi waits for input. Unit tests cannot replace real idle UI acceptance.
- **Bridge-down behavior is intentional.** Recall/capture/save must fail loud; no direct memory or plan-file fallback.
- **A Pi on older code still returns full recalls.** Recall is budgeted (~32 KB) only once Pi restarts on current source; an older Pi returned every engineering doc (723 KB in this repo), which exceeds some harness result limits. Inspect such a saved response with `jq`, selecting `.result.prompts.<mode>Prompt`, instead of loading it whole.
- **Live bridge tests must load current source.** Use `--no-extensions -e <repo-root>` (or explicit repository extension paths), not a stale installed package. Automated PTY runners must continuously drain Pi terminal output or the child can block and cause false request timeouts.
- **Claude MCP registration source matters.** A stale registration may point at an older package. Use `claude mcp get/list` to inspect, then `/harness` to repair from the current installed package; do not edit `~/.claude.json` directly.
- **Claude `/clear` can drift session identity.** Claude Code 2.1.296 print-mode `/clear` without session persistence changed session ID; this was not an interactive TUI test. Pass explicit `sessionId`: live client check confirmed it takes precedence over stale `CLAUDE_CODE_SESSION_ID`.
- **Claude Code 2.1.296 `UserPromptSubmit` `systemMessage` is not peer visibility.** On 2026-10-12 it was observed neither displayed nor model-visible; do not rely on it for peer visibility. Direct hook output through `hookSpecificOutput.additionalContext` does not verify interactive TUI behavior.
- **Cursor peer delivery is pull-only.** Cursor identity was exercised through the live bridge client with `harness: "cursor"`, not an interactive Cursor model session. Retrieve/ack replies with `read_messages`; do not assume a prompt hook injects peer messages.
- **Claude statusLine has one command slot.** Compose Pi indicator into that command; do not configure a competing statusline. `/harness` preserves a user-owned slot rather than replacing it. `refreshInterval: 5` parsed and `claude doctor` passed, and script emitted `Pi ✉1`; interactive idle redraw timing/appearance was not verified.
- **VS Code `additionalContext` peer-message delivery is unverified.** Do not treat it as proven hook/injection behavior.
- **Claude Bash rewriting depends on PreToolUse `updatedInput`.** If host stops honoring rewritten input, deny Bash rather than fall back to unsandboxed regex approval.
- **Sandbox bypass flags require explicit denial.** `dangerouslyDisableSandbox` must be rejected before wrapping.
- **Cursor hook verdicts use `permission`, not `decision`.** Command hooks must return `permission` plus supported `user_message`/`agent_message` fields; a `decision` key silently fails to enforce the verdict.
- **`afterFileEdit` has no preimage/output contract.** Cursor supplies edit metadata such as `edits[].old_string`, not exact pre-edit bytes or supported post-edit output fields. Do not attempt a post-write revert; `preToolUse` denies `Write` before execution.
- **Cursor shell classification is allowlisted by segment.** Split only on unquoted separators; every segment must be an allowlisted read with per-command flag checks. Dynamic syntax and hidden writers ask, and mutation tokens deny. New read commands and flags need deliberate allowlist updates; it is not a general shell. `ADR-0046`.
- **Cursor docs nudge is not a gate.** `.cursor/hooks/docs-nudge.js` asks on `git commit` when staged non-doc changes omit `docs/engineering/**`; malformed input and Git errors allow so commits are never blocked by the nudge.
- **Claude and Cursor bridge identity is agent-asserted.** MCP arguments choose `harness` and `sessionId`, so a same-user process can present another identity; OpenCode alone overwrites both from the host session (`agent/claude-bridge-client/pi-bridge-mcp.js:160-173`; `agent/opencode-bridge-client/pi-opencode-plugin.js:48-53`). `ADR-0045` F2.
- **Cursor shell prefix bypasses are fixed.** The old read-prefix classifier allowed chained interpreters, delete predicates, pipe-to-interpreter, and output flags; the segment allowlist now asks or denies those shapes. Per-command lists are SAFE flags, not bad flags: two reviews found writers and executors that bad-flag lists missed (`rg --hostname-bin`, `sort --compress-program`, GNU abbreviations like `sort --o`, `uniq - out`). Add a flag only when it cannot write or execute (`SAFE_FLAGS`, `FIND_SAFE_PRIMARIES` in `agent/cursor-bridge-client/cursor-readonly-hook.js`). Safe lists check argv before the shell expands globs, so an unquoted `*`, `?`, or `[` in any segment asks: expansion can add operands (`uniq *.txt`) or turn a file name into a flag. Quote patterns (`rg -g '*.md'`) to keep them allowed. Recorded limit: zsh with the non-default `EXTENDED_GLOB` option also expands `^`, `~`, and `#` patterns, which the hook still allows; abusing it also needs a planted flag-named file. `ADR-0046` F3, F13.
- **Git can execute programs from repo config.** `diff.external` and textconv drivers run on plain `git diff`/`log -p`/`show` even with safe flags. Exploiting this needs write access to `.git/config` (clone does not copy it), so it is a recorded limit, not a flag rule.
- **Cursor `preToolUse` is deny-unknown.** Only the read allowlist and shell/MCP passthrough types allow; every other tool name denies (`agent/cursor-bridge-client/cursor-readonly-hook.js:223-231`). Extend the constant set only from observed read names. `ADR-0046` F4.
- **Claude hook crash paths deny.** The hook wraps its main path so thrown errors emit a deny verdict, and setup appends an exit-2 guard to `PreToolUse` only; an unguarded owned entry is reported and repaired. Hook-timeout behavior remains unverified (`agent/claude-bridge-client/pi-readonly-hook.js:125-184`; `agent/extensions/harness-setup/setup.ts:788-793`). `ADR-0046` F5.
- **Live core-protocol test is stale for non-Pi Edit.** `agent/claude-bridge-client/test-core-protocol.js` still expects an `Edit` with empty `tool_input` outside a Pi project to pass, but since `038608a` the Claude hook denies a missing `file_path` there, so its two non-Pi Edit checks fail. The test is live-only, so CI does not catch it. A rerun in the same Pi session also inherits the previous run's saved plan and fails the no-plan precondition; use a fresh session per run.
- **Foreign MCP is never a silent pass.** Claude and Cursor ask on unknown foreign names, Cursor denies mutating names, and OpenCode throws on names outside its read/bridge allowlist. OpenCode plugin-load failure remains unverified (`agent/cursor-bridge-client/cursor-readonly-hook.js:210-216`; `agent/opencode-bridge-client/pi-opencode-plugin.js:80-82`). `ADR-0046` F6.

## Workflow modes and review

- **Shared workflow prompt fragments cross harnesses.** Fragments added to `composeWorkflowPrompt` reach Claude Code and Cursor through `agent/extensions/claude-bridge/index.ts:444-448`, where all four active-mode prompts are composed. Keep wording harness-neutral; a Pi-only tool name pushes other harnesses onto prose fallback.
- **Mode union is mirrored and has drifted before.** Keep the owner, Caveman union, engineering-docs union, subagents union, and subagents boolean guard aligned (`agent/extensions/workflow-modes/index.ts:16`, `agent/extensions/workflow-modes/caveman.ts:1`, `agent/extensions/engineering-docs/constants.ts:33`, `agent/extensions/subagents/index.ts:156`, `agent/extensions/subagents/index.ts:494-495`). The prose rule alone failed; `scripts/check-workspace.mjs:97-110` now parses all five sites, and the root check runs that guard (`package.json:56-58`).
- **Mode label maps retain a residual gap.** The guard does not parse either typed label record (`agent/extensions/workflow-modes/caveman.ts:5-12`, `agent/extensions/engineering-docs/mode.ts:28-35`). Workflow-modes runs `tsc` (`agent/extensions/workflow-modes/package.json:10-12`), but engineering-docs declares tests only and the root typecheck omits it (`agent/extensions/engineering-docs/package.json:5-7`, `package.json:62`); keep that label map aligned manually.
- **Subagent confirmation is not relayed.** The launch adapter accepts only `input` and `select`; it cancels `confirm`, which RPC maps to `false` (`agent/extensions/subagents/launch.ts:424-435, 990-1001`; `agent/extensions/subagents/node_modules/@earendil-works/pi-coding-agent/dist/modes/rpc/rpc-mode.js:84-85`). A child cannot authorize Review posting.
- **A relayed select is not posting approval.** Selects become ordinary child questions and can be answered through parent `subagent_message`; never treat that answer as human confirmation (`agent/extensions/subagents/index.ts:679-685, 1122-1130`).
- **Sanitize review commands before showing them in `pi-tui` Text.** `Text` wrapping preserves ANSI codes, so raw commands can manipulate the confirmation display (`agent/extensions/workflow-modes/policy.ts:34-39`; `agent/extensions/subagents/node_modules/@earendil-works/pi-tui/dist/components/text.js:58-59`).
- **Review body must be inline.** Read-only filesystem rules exclude body-file workflows.
- **Unsandboxed Plan and Review prompt for every bash command; unsandboxed Discuss runs none.** Without a launcher (for example Linux without bwrap), Plan and Review ask "Run without sandbox?" for each single-line command a deny list (and, for Review, its allow-list) does not catch; a gh posting command keeps only its posting confirm, and a multi-line review body is refused before any prompt (keep it on one line). Discuss denies bash entirely; use the read tool and any active search tool such as `ccc_search` (Pi does not activate grep/find/ls by default). Decline, headless, or a subagent's cancelled confirm blocks, so headless Plan and Review cannot run bash at all. Install bwrap to avoid this. macOS always wraps with Seatbelt; tests reach the fallback by removing the cwd so wrapping fails. Ubuntu CI has no launcher, so any test that expects a wrapped Discuss/Plan command must branch on `wrapCommand(...).wrapped`; one that did not broke Linux CI from round 3 until round 5. The prompt (like Review posting) escapes invisible Unicode (zero-width, bidi, non-ASCII spaces, blank fillers, variation selectors) as `\xNN`, `\uXXXX`, or `\u{X}`, and collapses every run of 4+ blank characters (spaces, newlines, or hidden characters) to one `[N spaces]` or `[N blank: ...]` marker, so padding cannot push the rest of a command out of view; the command still runs unchanged. Escaping alone was not enough: 2,000 no-break spaces became a 12,034-character wall of escapes.
- **Live GitHub checks require installed/authenticated `gh`.** Unit and typecheck success do not validate GitHub access.
- **Saved-plan pointers and progress are session ancestry; bodies are session-scoped agent files.** Bodies live under `<agentDir>/plans/<sessionId>/<planId>.md`, not in the repository, Git-branch store, or bridge directory. Ephemeral sessions do not promise restart persistence; never add a shared fallback plan file.
- **Plan files are immutable specs during Build.** `/plan save` writes the body atomically, Section 4 seeds branch-backed tasks, and `workflow_plan_tick` records progress. Do not edit plan checkboxes to claim completion; do not delete a referenced body. Age GC is limited to unreferenced files in the current session. Reconstruct plan state synchronously before awaiting session-start GC so prompt hooks cannot observe default mode/empty state.
- **Plan-file API changes require focused test updates.** Changing agentDir-first signatures without updating test call sites causes typecheck failures and misleading runtime path-safe errors; update fixtures before interpreting suite results.
- **Section 4 metadata is tolerant by design.** `plan-tasks.ts` accepts `**Given**`, `**When**`, and `**Then**` labels with or without a colon, including the template's same-line Given/When/Then form; optional `**Files:**` hints are preserved as `metadata.files` and remain advisory, never ownership. Keep malformed input on the empty-task path.
- **Stale saved plans anchor every active mode.** Active plan body and compact identity/progress marker enter Discuss, Plan, Build, and Review prompts every turn; use `/plan select` or `/plan clear` when active selection changes.
- **Section 4 completion is not full-plan completion.** Tracker progress uses Section 4 only; Section 5 Definition of Done remains a separate closure gate. Report both statuses instead of claiming the whole plan complete.
- **Custom entries and custom messages use different context channels.** Pi `pi.appendEntry()` custom entries stay out of LLM context; `before_agent_start.message` and `pi.sendMessage()` custom messages enter it, and `@earendil-works/pi-coding-agent/dist/core/messages.js:89-96` maps them to LLM role `user` while dropping `CustomMessage.details`. Put model-required tracker data in message `content`, not only `details`; prefix harness-authored content, as in `agent/extensions/workflow-modes/index.ts`.
- **One-shot custom messages do not survive compaction reliably.** `@earendil-works/pi-agent-core/dist/harness/compaction/compaction.js#findValidCutPoints` treats `custom_message` entries as valid cut points, so active-mode authority must be regenerated per turn; reserve one-shot announcements for Off transitions.
- **Seatbelt profile remains allow-default.** The generated profile is `(allow default)` plus network/write denials, not a read allowlist; a LaunchServices escape remains unproven. Treat this as an accepted limit, not a fixed issue (`agent/extensions/workflow-modes/sandbox.ts:45-61`; `agent/claude-bridge-client/pi-readonly-hook.js:71-86`). `ADR-0045` F8.

## Execution-aware review

- **Exit codes come from Pi's error text.** Pi's bash `tool_result` has no exit code in `details`; a non-zero exit throws with `Command exited with code N`. Capture parses that phrase and records `exit: null` with a warning when it is missing; a Pi wording change would silently degrade every failure to `null`. `test_review_capture.ts` pins the phrase against every installed Pi copy.
- **Parent hooks never see subagent tools.** Children launch with `--no-extensions`, so per-run evidence comes from the launch host's RPC events. Redact inside `launch.ts` while the run is live: `host.redactText` returns text unchanged once the run is released.
- **A blocked `tool_call` may never get a `tool_result`.** Pending captures are capped at 200 and reported as `incomplete`; never assume every call pairs with a result.
- **Redaction is pattern- and env-name-based.** A secret that matches no token shape and is not the value of a secret-named env var is kept. Read a bundle's `redactions` count and `warnings` before trusting it.
- **Harness-lease builds leave thin evidence.** A bridge tick has no Pi attempt, so its bundle is git-only and warns `unavailable: harness build commands`.
- **An equal baseline means nothing was captured.** An attempt's baseline is HEAD at its first recorded tool call. If that was already the ticked commit (the changes were made before Pi Build recorded anything), the diff is empty and the bundle warns `incomplete: baseline equals the ticked commit; changes were not captured`. Read the warnings before trusting an empty diff.
- **`**Files:**` hints are free text.** `parseFilesHint` (`review-bundle.ts`) counts only backticked spans when the hint has any; otherwise it splits on commas outside braces, drops `(notes)`, and keeps each entry's first word. Braces expand (at most 100 patterns), and entries without `/`, `.`, or `*` (such as `none`) are ignored. A hint that yields no patterns produces no outside-Files warning.
- **Size pages in escaped UTF-8 bytes.** Evidence pages sized by character count overflowed 24 KiB on CJK and emoji text.
- **Review recall releases the caller's lease.** Run review calls as a different identity from the implementer; the bridge e2e uses a second identity for review steps.
- **A running Pi uses its installed package.** Checkout changes to tick or review fields are invisible until Pi loads the new code; a tick reply without `by` means the old code answered.

## Engineering docs

- **Root spokes contain mixed ownership.** Generator may replace only managed `pi-docs` marker block in `AGENTS.md`/`CLAUDE.md`; surrounding bytes are user-owned.
- **Decision index is generated.** ADR changes can leave `/docs check --check` reporting stale index until `/docs update-index` runs in Build/Off.
- **ADR filenames carry descriptive suffixes.** Do not guess `ADR-0021.md`; discover exact paths with `find docs/engineering/decisions -maxdepth 1 -type f -print` before reading or editing.
- **Tag validator sees literal bracketed examples.** Plan boilerplate containing bare docs tags can be interpreted as real tags. Use exact valid area/action pairs in plan tasks.
- **Docs writes fail closed before workflow state arrives.** If workflow extension is absent/stale, docs extension reports Unknown and blocks writes.
- **Edit/write observers disagree on path identity.** `filechanges` resolves paths against `ctx.cwd` and captures at `tool_call` (`agent/extensions/filechanges/index.ts:51-56`, `agent/extensions/filechanges/index.ts:530-533`); engineering-docs observes successful `tool_result` without `ctx`, slash-normalizes the raw input, then uses substring checks (`agent/extensions/engineering-docs/tracking.ts:15-34`, `agent/extensions/engineering-docs/tracking.ts:63-82`). Their tracked sets can differ; inspect both paths when file-change UI and docs reminders disagree.

## File changes

- **Only successful Pi `edit`/`write` establishes baseline.** Bash, external editor, Cursor, or manual changes are not new tracked baselines.
- **Original text is stored in session.** Sensitive file edits can place preimage in Pi session history even if later declined.
- **Decline is destructive and text-oriented.** It deletes files created after absent baseline and overwrites existing files with recorded UTF-8 content.
- **Partial decline clears tracking after reporting errors.** Inspect warning/console and filesystem immediately; do not assume failed paths remain available for another tracked retry.
- **Accept/decline is not Git.** Neither action stages, commits, or restores untracked changes outside extension log.

## Pi subagents

- **Child tool surface is explicit.** Children launch with `--no-extensions` and the module-relative `child.ts`; only loadout-approved tools, `ask_question`, browser proxies, and allowlisted nested `subagent` are registered. Parent validates the toolset before launch.
- **Injected tools must be in the restricted allowlist.** Parent adds `ask_question` and, when configured, `subagent` before `validateSubagentToolset()` (`agent/extensions/subagents/index.ts`). Omitting either from `policy.ts` can refuse an otherwise valid non-Build launch.
- **Child extension path follows module location.** `resolveSubagentExtensionPath()` derives `child.ts` from `import.meta.url`; do not hard-code checkout paths. Source and npm installs have different absolute locations, and a missing path causes launch failure.
- **Do not use `readline` for RPC JSONL.** Node line readers may split on U+2028/U+2029 inside JSON strings. Decode LF-delimited records from byte chunks, strip an optional trailing CR, and enforce the 32 MiB record cap (`agent/extensions/subagents/rpc.ts`, `test/test_rpc.ts`).
- **A `pi` command on `PATH` may be a wrapper, not the CLI bundle.** Resolve the parent CLI script from `process.argv[1]` and spawn it with `process.execPath`; missing script path is a classified launch failure, not a reason to look up `pi` on `PATH` (`agent/extensions/subagents/rpc.ts`).
- **Prompt `disposition: handled` starts no child run.** It does not produce `agent_settled`; treat it as a classified launch failure. Older responses with no disposition mean `started` (`rpc.ts`, `launch.ts`).
- **RPC child questions do not time out.** Dismissing the parent dialog or lacking parent UI does not send a cancellation response; the question stays pending until answered or the run is cancelled/closed. Waiting pauses both watchdog budgets (`child.ts`, `launch.ts`).
- **Gate child relays while `/agents` is open.** The question owner serializes model and child dialogs, but does not own the `/agents` overlay. While any overlay is open, keep child questions queued; show the viewed child's question/options there, or show `<chain label> has a question; press Esc to answer it.` for another child. On Esc, dismiss/remove only the viewed child's queued prompt, keep its question pending, and show the answer-later warning; do not open its dialog. Other-child prompts stay queued and open after the last overlay closes. The dismissed question remains answerable through `/agents`.
- **R1 resolved for child-question ownership; model-over-`/agents` remains out of scope.** Child requests now use the `ask-user-question` event relay and share its FIFO with model questions, so those dialogs no longer compete. A model-initiated question can still open over `/agents`; that overlay interaction remains deferred.
- **`ctx.ui.custom()` is TUI-only.** RPC/non-TUI contexts cannot render the `/agents` overlay; the command must give an explicit interactive-TUI notice.
- **Dismissed child questions stay pending.** Reopen `/agents` or use the explicit `subagent_message` path when the user asks; do not treat dialog dismissal, overlay Esc, or an empty answer as cancellation of the child request.
- **The `/agents` overlay is TUI-only; child-question dialogs are not.** RPC/non-TUI parents with UI use the question owner's built-in `ctx.ui.select`/`ctx.ui.input` path. Without UI, the relay reports unavailable; answer the parked child through `/agents` from an interactive TUI.
- **Upstream `RpcClient` is not a drop-in.** It launches `node` from `PATH`, mirrors unbounded stderr to the parent TTY, and lacks the process-exit and extension-UI response hooks required here. Keep stderr piped to the bounded diagnostics sink and use the local process wrapper (`rpc.ts`).
- **`agent_end` is not final settlement.** Read final text only after `agent_settled` with `get_last_assistant_text`; a process exit before settlement is a classified failure (`rpc.ts`, `launch.ts`).
- **Child transcript stays out of parent context.** Final text reaches the parent through follow-up delivery; persisted child session is out-of-band evidence. Queueing is not receipt: matching `message_start` marks delivery, otherwise the result stays visible in `subagents_list`.
- **Nested graph is bounded.** `subagent_agents:` plus depth two controls recursion. Bundled worker allowlists explorer; explorer is leaf. User/project definitions still pass the same allowlist/depth checks (`agents.ts`, `policy.ts`, `index.ts`).
- **Slice fan-out can starve nested explorers.** Worker and nested launches share the same configurable default lane (`agent/extensions/subagents/concurrency.ts`); nested spawn waits for a slot while its worker holds one (`child.ts`, `launch.ts`). Three slice workers can occupy default capacity 3, leaving no slot for an explorer. Open tool calls pause idle timeout but max-total continues (`timeout.ts`), so starvation can last until the max-total backstop. Keep slice count ≤ min(2, cap−1) (two at default cap 3); if cap is unknown or below three, do not fan out.
- **Local agent definitions shadow bundled names.** Overrides remain active, but subagents warns once per file/session when bundled `tools`, `subagent_agents`, or `model` keys are missing. Check the named override path; add the missing keys or remove an unintended override.
- **Default scope is user.** A project test agent under `.pi/agents` is invisible when caller leaves `agentScope` at default.
- **`subagent_message` is not cancellation.** For a running child it sends RPC `steer`, delivered at the child's next tool boundary; an active tool must finish first. Pending-question answers and finished-session resumes retain their separate paths. Parent cancellation sends RPC `abort`, then closes stdin and escalates to `SIGTERM` after one second and `SIGKILL` 500ms later (`launch.ts`, `rpc.ts`).
- **Esc can restore follow-up text without proving delivery.** It restores queued `sendUserMessage` text to the editor but drops custom follow-ups. If the user edits restored result text before submitting, no exact `message_start` receipt occurs; the result remains pending in `subagents_list` and is not auto-duplicated.
- **A busy parent delays subagent result follow-ups.** At the first settle check, exact text already in the editor becomes user-owned; otherwise one `subagent-result` `nextTurn` fallback is queued without auto-starting a turn. Do not poll `subagents_list` to hurry delivery; use it for status, transcript, or log lookup.
- **Only nested spawn may use `noDeadline`.** `ask_question` uses RPC UI, not IPC; ordinary `browser` and `ownership` IPC requests keep bounded deadlines. A side-channel disconnect rejects its pending requests but does not fail the run (`ipc.ts`, `child.ts`, `launch.ts`).
- **A parent death closes child stdin.** RPC mode exits on stdin EOF; do not detach the child or substitute a background launch that can outlive its parent (`rpc.ts`).
- **Child stderr never goes to the parent TTY.** RPC stderr is piped into a log capped at 1 MiB; the in-memory event/text tail is capped at 8 KiB. The per-run token must be redacted from logs, tails, and failure text; keep new diagnostics on the same redaction path (`diagnostics.ts`, `launch.ts`).
- **Child session IDs are not transcript filenames.** `childSessionId` identifies a run but may not match a file on disk. Use the reported `sessionFile`/`Transcript` path from `subagents_list` or failure follow-up; never infer a transcript path from the ID.
- **Progress callbacks can outlive teardown.** Clear scheduled redraws and tolerate stale UI context on finish/failure.
- **Worker ownership guards are host-local.** `OwnershipLockManager` prevents overlap among children served by one parent host; it does not coordinate another Pi process or external editor (`ownership.ts`).
- **Browser proxy owner is IPC identity.** Child browser requests must retain child owner and request correlation; parent browser event handling must not fall back to `parent` owner, or pages/buffers can be shared accidentally (`launch.ts`, `index.ts`, `agent/extensions/browser/index.ts`).
- **Returned error text is not a tool error.** Pi can record `isError: false` and show parent progress as `— ok`; Pi 0.80.x ignores returned `isError: true`. Child proxies must throw `Error` with unchanged model-visible text so parent progress marks failures `— error` (`agent/extensions/subagents/child.ts`; `pi-agent-core/dist/agent-loop.js`).
- **`--no-extensions` disables built-ins too.** Pi 1.2.0 disables discovered, configured, and built-in extensions, including `builtin:mcp`, `builtin:tool-search`, `builtin:codemode`, and `builtin:llama.cpp`; explicit `-e child.ts` still loads (`agent/extensions/subagents/launch.ts`; Pi 1.2.0 `docs/cli.md`, `docs/settings.md`).
- **`--tools` does not filter MCP by default.** Pi 1.2.0 keeps every `mcp__*` tool unless an allowlist entry starts with `mcp__`; do not rely on `--tools` to close MCP exposure (Pi 1.2.0 `docs/cli.md`, `docs/mcp.md`).
- **`--no-approve` silently drops project resources.** It skips trust-gated project skills, packages, and `.pi/mcp.json`; it does not preserve project resources while only suppressing a prompt. Mirror parent trust (`agent/extensions/subagents/index.ts`, `agent/extensions/subagents/launch.ts`; Pi 1.2.0 `docs/security.md`, `docs/packages.md`, `docs/mcp.md`).
- **Child browser proxies use the parent's gate.** The browser gate defaults off; proxy calls fail until the parent runs `/browser on` (`agent/extensions/browser/index.ts`, `agent/extensions/subagents/child.ts`).

Workaround: copy the packaged `agent/harness-commands/cursor/pi-*.md` files into a consumer project's `.cursor/commands/`. This repository's `.cursor/commands/pi-*` symlinks are repo-only.

Review the preview and Pi's skill-collision warning; another first-discovered skill with the same name can shadow the package skill.

Skills with `disable-model-invocation: true` (`grill`, `grill-with-docs`) are absent from model-visible skill lists by design; verify them by direct slash invocation.

- **Harness config must be strict JSON.** JSONC, malformed, unreadable, or oversized config is unsupported; `/harness` skips that file without writing it, while independent planned files may proceed.
- **Legacy bridge-client copies are not package installs.** `~/.pi/agent/*-bridge-client` copies are not authoritative package roots; install through Pi and let `/harness` manage paths from the installed package.

- OpenCode `v2.0.32` loads global plugins from `~/.config/opencode/plugins/`; an isolated plugin loaded under Bun, and `createRequire()` loaded `pi-bridge-mcp.js`. This runtime requires default export `{ id, setup }`; a function-style default export failed with `Plugin must export a default definition with an id and an effect or setup function.` The setup context exposes `tool.hook`; `command` has only `list`, `reload`, and `transform`.

MCP tools appear in the Code Mode catalog (`pi-claude-bridge (12 tools, 8 shown)`), not as top-level model functions. For this runtime, mutate `event.input` on the one-argument event object; there is no separate `output.args` parameter.

It intentionally leaves outer `execute` available as dispatcher; `test-opencode-plugin.js` covers these boundaries. ## Codex harness

- **Codex hooks fail open.** Codex runs the tool when a PreToolUse hook times out, prints malformed or unsupported output (including `permissionDecision: "ask"`), or exits non-zero without a usable verdict. Exit 2 blocks only with a stderr reason, so the installed guard is `|| { echo 'Pi Codex hook failed closed' >&2; exit 2; }`; plain `|| exit 2` lets silent failures through. Real Node crashes print to stderr; the corpus `silent` variant is the only discriminating case. ADR-0045 F14 accepts the rest.
- **Hook trust is per surface and silent in `codex exec`.** The CLI (`/hooks`) and the desktop app (Settings > Hooks) trust hooks separately. The CLI stores trust in `config.toml` `[hooks.state."<hooks.json>:<event>:<group>:<handler>"]` keyed by position and definition, not script contents, so moving the hook or changing its command needs re-trust while a package upgrade at the same path does not. Untrusted hooks are skipped with no warning in `codex exec`. In `/hooks`, trust only the Pi hook; `t` trusts every plugin hook too.
- **Codex's sandbox keeps `.git` read-only.** Under `workspace-write`, `$pi-build` can edit files with a lease but `git add`/`commit` fail with `.git/index.lock: Operation not permitted`. Commit needs Codex escalation: the desktop app prompts; in the CLI choose an approval mode with `/permissions`. `codex exec` (approval `never`), including resumed exec sessions, cannot commit.
- **Codex tool names differ by surface and version.** Both surfaces route tools through a Code-Mode `exec` dispatcher (nested calls reach the hook; the outer call does not). The question tool is `request_user_input` in the CLI and `request_user_input_async` in the desktop app. Unified exec appears as `Bash`; MCP servers are normalized (`pi-claude-bridge` -> `mcp__pi_claude_bridge__*`). Re-check the hook allowlist after Codex upgrades.
- **Dynamic shell is blocked before a lease.** `classifyShell` denies `$(...)`, backticks, loops, redirects, and unquoted globs, and Codex cannot ask. Codex skills detect `.pi/` with plain `ls -a`, `ls -a ..`; a model that probes with `$(dirname ...)` stops before `recall_memory`.
- **Codex skills release the lease if misused.** Running `$pi-discuss` or `$pi-plan` while holding a lease recalls Discuss/Plan and releases it. The skills set `allow_implicit_invocation: false` so they never auto-trigger. Pi's lease messages still say `/pi-build`; Codex users type `$pi-build`.
- **The desktop app rewrites `config.toml`.** It and the CLI add `[projects.*]` trust, `[hooks.state.*]`, and UI tables, and may reformat. `/harness` therefore owns the bridge table by content and changes no other byte; a foreign or unusual `pi-claude-bridge` definition is reported and preserved.
- **Some writes never reach a hook.** Hosted tools (web search) skip PreToolUse, and MCP server processes run code at startup (cocoindex created `.cocoindex_code/` in a Pi project when Codex opened). Treat both as outside Pi enforcement.

## Security regression corpus

- **Git reads can rewrite `.git/index` stat cache.** The corpus snapshot hashes repo files except `.git/index` and also includes `git ls-files -s`; removing the exclusion can report false mutations, while dropping the Git listing can miss tracked-state changes.
- **Inherited Git/XDG variables can redirect fixture state.** `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, and other inherited `GIT_*` values can point Git outside disposable repo; inherited `XDG_CONFIG_HOME` can redirect config. Runner removes inherited `GIT_*`, sets `GIT_CONFIG_NOSYSTEM=1`, and resets `XDG_CONFIG_HOME` under temporary `HOME`.
- **bwrap tmpfs scratch can hide repo.** `--tmpfs` overlays its target; if scratch path equals repo or contains it, command's repo view is masked. Keep runner scratch separate from repo; wrapper recognition of `--ro-bind / /` and `--unshare-net` does not prove mount topology.
- **bwrap's read-only root can make `/dev/null` unwritable.** On GitHub ubuntu runners from 2026-11, `--ro-bind / /` alone left `/dev/null` read-only: login-shell profile scripts failed with "/dev/null: Permission denied" and sandboxed git reads exited 128 (8 `test:security` cases, `main` included). `buildBubblewrapCommand` must keep `--dev /dev` after the root bind, which gives a fresh minimal device tree while the root stays read-only (`agent/extensions/workflow-modes/sandbox.ts`, `test/test_sandbox.ts`). A failed corpus read prints its stderr summary, so the next such cause shows in the CI log.
- **Cross-session writer cases are regression pins, not gaps.** F10 is closed: `lease-cross-session-write`, `lease-cross-session-pi-build`, and `lease-cross-session-stale` assert that another live session's lease or Pi Build blocks the holder and that stale presence does not. Do not reintroduce a check that looks only at the paired session.
- **Do not classify unsandboxed shell as safe for Pi.** Two review rounds each found new flags that let a "read" command write or execute (`rg --pre`/`--hostname-bin`, `sed -i`, `sort -o`/`--compress-program`, `uniq - out`, ...). Pi's no-sandbox fallback therefore never auto-runs: F9/F12 are closed by approval, not parsing. Review's allow-list had the same flaw without a sandbox until round 5 and now asks too. The corpus models the fallback with `noSandboxDecision`, the handler's own function, not a stand-in: unsandboxed Plan expects `ask` for approval-gated commands (Pi read default, `pi-plan-wildcard-test`, most `pi-fallback-*`) and `deny` for multi-line, `<>`, and deny-listed ones; Discuss expects `deny`. A stand-in that always said deny hid the difference between "asks a human" and "never runs". Prefer structural sandboxing where available.
- **Cursor `failClosed` is only asserted at config level.** The runner checks installed `failClosed: true` and verifies broken hooks exit nonzero; actual Cursor host enforcement of that exit is outside the runner.
- **OpenCode plugin-load failure is a host limit.** The runner verifies a broken installed plugin fails during import, but cannot establish how OpenCode handles that failure.
- **Sandbox-disabled lane is separate evidence.** `npm run test:security` runs a second pass with existing `PI_READONLY_HOOK_DISABLE_SANDBOX_EXEC=1` and forces Pi `piLauncher: "none"`; it tests external-hook and Pi fallback decisions. Eligible raw `allow` commands still require runner Seatbelt confinement on macOS; without it they are skipped.
- **K1: Seatbelt cannot nest.** Product wrapper executes without an outer Seatbelt layer, so a profile regression could write outside repo before repo snapshot. Recognizer checks deny-write/network text and product-profile assertions mitigate this, not proof of full outside-repo confinement.

## Harness Build lease traps

- Build completion releases the lease as soon as the final task tick lands. Commit first, then tick; a post-tick commit can be denied (`agent/harness-commands/*/build.md`, `.cursor/commands/pi-build.md`).
- Resume and tree navigation no longer restore Build: a branch whose latest mode is Build lands in Plan with a durable entry and a notice, so users re-enter Build with the guarded `/mode build`. Tests that need Build must enter it through `/mode build`, not by restoring a Build branch. `/reload` lands in Plan too: a round-4 reload exception let a session whose Plan save had failed reload straight back into Build and re-claim the writer. The landing never rejects, and a throwing status update cannot skip it. Do not re-derive the mode from the branch anywhere else: `/plan select` and `/plan clear` once did, which let a session whose landing save failed slip back into Build. A branch that cannot be read in full restores Unknown with a warning and no plan state; pick a mode with `/mode`. Never skip a corrupt entry to keep going: skipping let an older mode (Off) or a cleared plan win, and stale plan state after a failed restore kept a Build lease alive. Unknown runs only read-only tools.
- Pi Off is intentionally unguarded. Treat it as opting out of workflow guardrails, not as an exclusive-writer guarantee.
- A granted harness lease has fixed four-hour expiry (`expiresAt`). Repeated `/pi-build` does not extend it; if expiry lands mid-build, the next write or tick is denied. Stop and request fresh human approval in interactive Pi, then rerun `/pi-build`. Headless Pi returns `build_lease_no_approval` without recording a request.
- If a harness exits while Pi stays live, holder unpair or `/build-lease release` revokes its lease; otherwise it remains until lifecycle change or four-hour expiry. If Pi exits/crashes, stale presence fails closed after the five-second heartbeat TTL; a stale lease field never authorizes writes.
- OpenCode task subagents may have a different host `sessionID` from their parent. If identity differs, their writes remain read-only; unit tests do not prove identity inheritance. Verify only in isolated live acceptance.
- **Self-grant trap fixed by ADR-0047.** Build recall creates or refreshes a pending request; only human confirmation in interactive Pi `/build-lease approve` grants after revalidation. Agent-supplied `save_plan` confirmation does not authorize a lease.
- **Conflicting writer claims deny everyone.** Two approvals or Build entries within one heartbeat, or a holder that stalls past the five-second presence TTL and resumes after another session acquired, leave two live claims. Every write, tick, and approval then refuses until one session runs `/build-lease release` or leaves Build; `/build-lease` lists the conflict. There is no tie-break by design.
- **The project-wide check sees only sessions with an active bridge.** A session whose bridge is passive publishes no presence, so its Build guard now blocks with the passive reason until the bridge is active again. That includes a bridge whose startup throws after it finds the project: it goes passive with `bridge startup failed: ...` instead of leaving Build unguarded. A session outside any Pi project has no bridge and no project check.
- **An abandoned bridge namespace is reclaimed after 60s.** A namespace directory with no readable presence (a startup that threw after creating it, or a crash before the first heartbeat) blocks that Pi session's bridge with `bridge namespace has no presence yet ...; retry session start`. Stale-namespace GC, which every claim runs first, removes it once its directory has been unchanged for over 60s (`isAbandonedNamespace` in `agent/extensions/claude-bridge/presence.ts`), so the next start a minute later recovers without manual cleanup. Live owners rename a fresh presence file into the directory every heartbeat, so their mtime never ages. Accepted limit: the age compares the file system's mtime with the local clock, so on a network or VM mount whose clock runs over 60s behind, an initializing namespace can look abandoned and be removed; that fails closed (its owner goes passive and retries).
- **A failing heartbeat warns once and retries.** A presence write error (for example a full disk or changed permissions) no longer escapes the heartbeat timer and ends Pi. The bridge warns once per failure streak and keeps retrying; meanwhile its own presence goes stale within five seconds, so the Build guard (`SELF_PRESENCE_STALE_BLOCKER`) and harness hooks keep writes blocked until a write succeeds. Two accepted limits: a failure that alternates with successes warns once per streak, so a flapping disk is noisy; and other presence refreshes (`refreshPresenceBestEffort`) still warn on every failure.
- **Pi's event bus swallows listener errors.** Listeners run inside an async try/catch that only logs, so a guard listener that throws before setting `blockedBy` would look like "no blocker". The bridge listener sets a provisional blocker first, and `getBuildGuardBlocker` fails closed when `emit` throws.
- **Running worker subagents finish their current run.** Children do not load workflow-modes. The Build guard blocks new `subagent` and `subagent_message` calls under a conflict, but a worker started earlier keeps its toolset after Pi leaves Build or another session claims the writer. Accepted limit (ADR-0051).
- **Two writer-claim implementations must stay mirrored.** `hasOtherWriterClaim` (`agent/claude-bridge-client/pi-bridge-mcp.js`) and `otherWriterClaims`/`parseBuildLease` (`agent/extensions/claude-bridge/build-lease.ts`) apply one rule in JS and TS, including liberal claim liveness (JS `scanSessions` entries with any `strict` value, TS `listLiveNamespaces(..., { forClaims: true })`). Only claim counting is liberal; pairing, peer restore, and `/claude-bridge` stay strict. Change both with mirrored tests. TS `parsePresence` once dropped `buildLease`, which hid other sessions' leases from Pi.
- **A stale own presence blocks only this session.** `writePresence` skips silently when bridge directories are not private, so the session's own presence goes stale and every Pi-side writer check fails closed with a message pointing at `.pi/memory/bridge` permissions or a restart.
- **Older installed hooks lack the cross-session check.** Hook scripts load from the installed package path; update the package and run `/harness` → Install / repair so every harness uses the current `holdsBuildLease`.

## Personal memory and discussion notes

- **Current personal memory is indexed directory, not flat append file.** `~/.pi/memory.md` is legacy migration input only; active entries live under `~/.pi/memory/` with generated `MEMORY.md`.
- **Index can still bloat prompt.** Keep entry names/descriptions concise; fetch full body only by validated slug.
- **Non-conforming legacy Markdown is preserved but not indexed.** Do not bulk-delete unknown files during migration/cleanup.
- **Bridge capture is not memory capture.** It updates selected-branch discussion notes only. `/notes promote` is current-project engineering-doc curation; `/remember` is Pi user-global curation. Never swap destinations.
- **Curation is visible but model-behavioral.** Command dispatch and deterministic writes are host-owned, but classification/merging uses the current session model. Require successful `remember` or edit/write results before claiming persistence.
- **Pi 0.83.0 print command dispatch cannot start curation turns.** Direct/follow-up `sendUserMessage` hangs, `sendMessage({ triggerTurn: true })` exits without a turn, and deferred sends use stale context. Print-mode curation therefore bypasses command registration and transforms input; deterministic notices use `writeSync(1, ...)` because ordinary extension stdout is redirected to stderr. Remove shim when command dispatch becomes awaitable.
- **Explicit slug means replacement.** `remember` with a slug overwrites that exact indexed entry after validation; recall it first and send the complete merged lesson.
- **Memory write serialization is process-local.** Parallel writes in one Pi process queue around `MEMORY.md`; separate Pi processes can still race until cross-process locking is introduced.
- **Discussion notes and prompts are bounded.** Note text over 480 characters fails; filtered listing uses 50-note/50-KiB pages, and oversized project-promotion prompts fail rather than truncate lessons silently.

## Terminal notification

- **Notification protocol depends on terminal environment.** Windows Terminal, Kitty, and OSC-777 terminals use different paths; unsupported terminals may show nothing or render escape sequences.
- **`agent_end` may fire during automated/non-interactive work.** Notification output is side effect, not proof verification succeeded.

## Cleanup

- **Foreground exit is safest.** Use `/quit` or interrupt, wait for process, then remove ignored bridge state.
- **Do not leave tmux/background Pi alive.** Old heartbeat causes passive bridge and tests hit wrong code.
- **Cleanup order matters.** Stop bridge owner before deleting `.pi/memory/bridge`; otherwise watcher can recreate files or emit errors.
