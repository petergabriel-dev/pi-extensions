| [ADR-0001](ADR-0001-pi-claude-bridge-boundary.md) | Active | Pi is source of truth; Claude Code is a thin read-only bridge client requiring live Pi and fail-loud behavior. | changing bridge protocol, Claude commands, memory/docs capture, read-only hooks, or workflow plan handoff |
| [ADR-0002](ADR-0002-reliable-persistent-memory-reconciliation.md) | Superseded | Superseded by ADR-0011; previously defined partial application, re-staging leftovers, repair retry, and dead-lettering. | reading historical reconciliation behavior before per-candidate orchestration |
| [ADR-0003](ADR-0003-non-blocking-reason-aware-persistent-memory-consolidation.md) | Active | Memory consolidation timing relies on transition reasons: reload transitions bypass model work, starts run in background with terminal staging consumption, and quit shutdown blocks. Background swaps are generation-guarded. | modifying session lifecycle startup/shutdown events, staging consumption, or debugging SQLite closed/lock errors |
| [ADR-0004](ADR-0004-pi-subagents.md) | Active | Pi subagents use persisted in-process child sessions, structured-return-only parent context, a parent-enforced worker Build gate, bounded main→worker→explorer graph, and concurrency lanes with ownership guards. | modifying subagent spawning, worker/explorer tools, workflow gates, concurrency, nested delegation, or child session persistence |
| [ADR-0005](ADR-0005-pinned-default-persistent-memory-careful-model.md) | Active | Persistent-memory model resolution: extraction defaults to `opencode-go/glm-5.1` (heavy), adjudication defaults to `opencode-go/glm-4-flash` (small/fast); env overrides win and unresolvable/no-auth falls back to `ctx.model`. | touching persistent-memory model resolution, troubleshooting consolidation timeouts/cost, adding model roles, or changing default providers/models |
| [ADR-0006](ADR-0006-chunked-persistent-memory-reconciliation.md) | Superseded | Superseded by ADR-0011; previously defined chunked model reconciliation with sequential apply/re-read and generation guards. | reading historical chunked reconciliation behavior |
| [ADR-0007](ADR-0007-workflow-modes-subagent-delegation.md) | Active | Workflow modes use prompt-only delegation guidance: Discuss/Plan route explorer work by threshold, and Build uses sequential one-worker-per-substantial-saved-task orchestration while parent gates remain authoritative. | changing workflow-mode prompts, subagent tool contracts, worker-orchestration guidance, or saved-plan delegation behavior |
| [ADR-0008](ADR-0008-persistent-memory-reconcile-connection-ownership-observability.md) | Active | Manual memory reconciliation owns its SQLite connection, uses single-flight and generation-guarded swap/discard, exposes bounded reconcile run observability, and uses incremental per-candidate sqlite writes instead of a final full rebuild-and-swap after candidate commits. | touching persistent-memory reconcile entrypoints, SQLite lifecycle handling, `/memory status`, run-log storage, memory meter UI, or incremental-vs-full index rebuild behavior |
| [ADR-0009](ADR-0009-bridge-staging-validity-malformed-quarantine.md) | Active | Bridge lesson captures stay lessons by deriving valid triggers, while malformed staging is repair-attempted before unrepairable files are dead-lettered and removed from staging. | changing bridge capture staging, lesson trigger validation, staging repair/quarantine, or `/memory deadletter` behavior |
| [ADR-0010](ADR-0010-subagent-idle-timeout.md) | Active | Subagent timeout behavior uses an idle watchdog reset by child events plus an absolute max-total backstop, with structured failure metadata. | changing subagent timeout semantics, subagent tool schemas/settings, or failed subagent result handling |
| [ADR-0011](ADR-0011-per-candidate-persistent-memory-reconciliation.md) | Active | Persistent-memory reconciliation uses per-candidate monotonic progress: deterministic add for empty shortlists, bounded lesson adjudication for collisions, and terminal dead-letter isolation for failures. | changing persistent-memory reconciliation, shortlist/adjudication routing, staging cleanup, dead-letter behavior, or crash-safety semantics |
